Goal

Build an internal Jira automation toolkit — Release Orchestrator MCP — so the team can manage releases, deployment tracking, and change tickets from one configurable workspace in Cursor, without repetitive manual Jira work every week.

Description

Standardize how the team prepares releases, creates and consolidates TCKT change tickets, posts structured deployment comments, generates Word release notes, and keeps a deployment history across multiple Jira projects (for example PIC, AN, and service desk). One ticket list drives notes, SharePoint, the change ticket, Slack, Outlook, and Teams — so copy-paste, missed fields, and inconsistent release documentation drop away. Program settings (Glofox, Ignite, approvers, channels) live in shared config; you run the flow by talking to the MCP in Cursor, not in a separate web app.

Success looks like

  • Any supported release can be prepared and reviewed in one guided flow in Cursor.
  • Deployment details are parsed, posted to Jira, and tracked with history you can look up later.
  • Change tickets are created with validated approvers, test/backout/impact plans, and a preview (and diff) before submit.
  • Release notes documents are generated from Jira tickets, grouped by dashboard or report.
  • Multi-project releases (standard + custom, multiple fix versions) work from the same configuration.
  • Release managers and analysts can run deployments independently after a short walkthrough of this guide.

What we achieve

  • A consistent release and deployment process instead of ad-hoc Jira updates and side spreadsheets.
  • Faster, error-free TCKT creation with pre-flight validation before anything is submitted.
  • Automatic release notes and an audit trail of who deployed what and when.
  • Fewer duplicate deployment comments and missed Done transitions after prod.
  • DORA-style visibility into deployment frequency and lead time from recorded history.
  • One toolkit reusable across BI and engineering workspaces that share the same release pattern.

What we use it for

  • Preparing multi-project releases before a production deploy.
  • Creating and consolidating TCKT change tickets for dashboard or report updates.
  • Posting structured deployment comments on tickets after a successful release.
  • Generating Word release notes (and client notes where needed) for stakeholders.
  • Tracking deployment history and marking releases complete when prod is verified.
  • Service desk and approver workflows with preview before create.
  • Slack deploy posts, Outlook mail, Teams review calls, and SharePoint uploads in the same run.
  • Choosing safe deploy dates (no Friday deploys, holiday-aware scheduling).

What problem it solves

Before

Tickets in Jira, notes in Word, TCKT fields pasted by hand, deployment comments rewritten every release, Done transitions forgotten, history in someone’s spreadsheet. Same report listed three times. Easy to miss approvers, testers, or a holiday.

With the MCP

One list in Cursor drives notes, SharePoint, TCKT, deployment comments, and announcements. Pre-flight checks catch bad fields before submit. You preview every Jira write and every Slack or mail send. Deploy dates skip Fridays and bad holiday gaps.

You stay in control — preview first, confirm every live send.

How fast it is

When tickets already have the right Jira comments, the MCP runs the full path in one session — load tickets, notes, SharePoint, change ticket, Slack, and Outlook previews — in about 5–15 minutes. Manual work used to spread across half a day.

Simple flow (every release)

flowchart TD A["Setup in Cursor"] --> B["Pick version and program"] B --> C["Review tickets in Jira"] C --> D["Teams review call"] D --> E["Release notes + client notes"] E --> F["SharePoint upload"] F --> G["Create change ticket"] G --> H["Slack deploy post"] H --> I["Outlook and Slack to team"] I --> J["Production deploy when ready"]

Leadership gets notified when the change ticket exists. Assignees get a Jira reminder on their tickets. Deploy only on a safe workday (not Friday).

Quick onboarding (new users)

  1. Open the Release Orchestrator repo in Cursor.
  2. Say Setup Release Orchestrator and sign in to Jira, Slack, and Outlook when asked (once).
  3. Reload the MCP in Cursor.
  4. Start a release: choose program (Glofox or Ignite), pick versions, follow the steps in order.
  5. Always preview Slack and email before sending live.
